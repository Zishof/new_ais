# Phase 4 contract audit: Monitor Kehadiran Pegawai Harian

`public.status_kehadiran_karyawan_harian` is the selected Phase 4 vertical business slice. The
first increment is deliberately a read-only daily monitor: it joins active employees to their most
recent attendance row for a selected date, but does not reproduce any legacy render-time mutation.

The machine-readable snapshot is
[`phase-4-daily-attendance-contract.json`](phase-4-daily-attendance-contract.json). Discovery was
performed on 2026-09-04 with PostgreSQL `default_transaction_read_only=on` against the `ais` source.
No source table, sequence, audit row, or control-plane route was changed during discovery.

## Legacy user journey

Legacy menu `10000269`, **Absensi Kehadiran Pegawai Harian**, owns
`/pages/master/absensi_kehadiran_pegawai_harian.zul`. Its list filters active employees by NIP/code,
name, status, work-unit subtree, and whether any attendance row exists. Selecting an employee opens
a monthly detail grid with date, status, check-in/check-out, hours, shift, overtime, early/late
metrics, note, and actions.

That detail renderer is not read-only. `AbsensiKehadiranPegawaiHarianHelper.loadData` calls legacy
helpers that can create or refresh rows and `autoUpdatePulangDariSejarah` can persist a missing
check-out while the grid is loading. AIS Next therefore does not call those helpers and does not
port their side effects into a GET request.

## Bounded projection contract

The first Next route is `/attendance/daily`; its versioned JSON boundary is
`/api/v1/attendance/daily`. A request selects one ISO date, an optional case-insensitive employee
name/number fragment, a record state (`ALL`, `RECORDED`, or `UNRECORDED`), and a bounded page. The
result exposes:

- employee ID, employee number (`mycode`, falling back to `code`), name, and active flag;
- the selected date;
- latest matching attendance ID, status code/name, check-in, check-out, and note; and
- an explicit `RECORDED` or `UNRECORDED` state.

Only employees where `pegawai.aktif` is true or null participate, matching the legacy list. If
more than one attendance row exists for the same employee and date, the row with the greatest
attendance ID wins deterministically. Missing status references remain visible with blank status
labels. Sort order is normalized employee name then employee ID. Page size is capped at 100.

The source snapshot contains 20 active attendance statuses but currently contains zero employees
and zero daily attendance rows. Source parity must therefore assert the legitimate empty state and
the status fingerprint `0ada97a9283caa5f1bae3bf4e9f65ddd`. Non-empty UI and API scenarios use
clone-only fixtures and must restore the clone afterwards.

## Physical contract

The projection reads only these legacy relations:

| Relation | Required columns |
|---|---|
| `public.pegawai` | `id`, `mycode`, `code`, `nama`, `aktif` |
| `public.status_kehadiran_karyawan_harian` | `id`, `pegawai`, `tanggal`, `statusabsensi`, `masuk_jam`, `pulang_jam`, `keterangan_absen` |
| `public.statusabsensi` | `id`, `kode`, `nama` |

Primary keys are bigint values generated by legacy sequences. Attendance has foreign keys to
employee and status; all selected business fields except the primary keys and status code/name are
nullable. The existing `(pegawai, tanggal)` and date-only indexes support the read path. The
five-relation discovery fingerprint, including adjacent status/work-unit contracts, is
`29d2d52323fc29ad02fdd7d3d3185e06`.

No DDL, sequence access, entity materialization, lazy association, or Hibernate session is needed.
The adapter uses a parameterized JDBC projection and a closed record-state enum.

## Authorization and route ownership

Read requires `LEGACY_MENU_10000269_READ`, derived server-side from the authenticated legacy role.
The observed source privileges grant all four CRUD flags to roles `Akademik` and `am`; role `maha`
is explicitly denied. AIS Next exposes only read, even when the role also owns create/update/delete.

Both HTML and API prefixes remain `LEGACY`/`LEGACY_WRITE` for the normal `local` tenant. They may be
set to `NEXT`/`NEXT_READ_ONLY` only for the isolated `uat-local` clone. A missing, ambiguous, or
legacy-owned route fails closed before controller execution.

## Excluded behavior

This increment does not create attendance rows, synchronize shifts, edit manual times, lock rows,
derive payroll totals, resolve photos/locations, infer holidays/leave, or repair scan history. Those
behaviors span additional aggregates and have observable writes; each needs its own owner, audit,
concurrency, and parity contract before migration.

## Phase 4 gates

The slice can close its technical gate only after:

1. repository and HTTP tests prove parameters, paging bounds, exact role negatives, and no writes;
2. source and Next produce the same empty-state fingerprint;
3. clone-only fixtures prove recorded/unrecorded selection and deterministic duplicate handling;
4. desktop/mobile accessibility checks reach the authenticated daily monitor; and
5. a CORE database outage produces a controlled unavailable response and recovers without restart.

Domain-owner acceptance remains a separate release gate. Production routing cannot be enabled by
this technical implementation.
